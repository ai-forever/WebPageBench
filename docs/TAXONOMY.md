# Таксономия задач (WebPageBench)

Классификация **типов UI-взаимодействий** (кнопки, поиск, даты, select и т.д.) — в отдельном [UI_TAXONOMY.md](./UI_TAXONOMY.md).

Канон бенчмарка — **только** `tests/bench`: **152 задачи** (65 канонических сценариев + 87 вариантов контролов и тёмной темы), единый хаб с **шестью** разделами. Успех — **Event-Match Score (EMS)**: совпадение типизированных событий из лога интерфейса с `conditions` задачи. Исторические прогоны в `liderboard/results/` не переписываются.

## Оси классификации

Каждый JSON в `tests/bench/tasks/` описывается по осям:

1. **Раздел (вкладка хаба)** — Маркет, Книги, Продукты, Поезда, Отели, Файлы; ключ `test_data.bench_first_domain` (`shop`, `books`, `grocery`, `rail`, `hotels`, `files`).
2. **Домен таксономии** — `ecommerce`, `digital_books`, `hotel_travel`, `rail_travel`, `document_cabinet`. У Маркета и Продуктов домен один (`ecommerce`); разделение — по вкладке и префиксу `view_type`.
3. **Категория** — семейство внутри домена: `product_catalog`, `ticketing`, `search_booking`, `document_cabinet`.
4. **Подкатегория** — `snake_case` стем файла задачи (`ecommerce_basket_named_product`, `rail_book_to_cart`, …).
5. **Варианты** — модификаторы в имени или стиле промпта:
   - `typo_in_prompt` — `*_typo*`
   - `price_constraint` — корзина с ценовым диапазоном
   - `multi_passenger` — несколько пассажиров в ЖД
   - `multi_sku` — несколько разных товаров в корзине
6. **Сложность** — по числу элементов в `conditions`: низкая (≤2), средняя (3–6), высокая (≥7).
7. **События проверки** — уникальные `event_name` из `test_data.conditions`.
8. **Класс UI** — `test_data.ui_taxonomy.primary` (см. [UI_TAXONOMY.md](./UI_TAXONOMY.md)).
